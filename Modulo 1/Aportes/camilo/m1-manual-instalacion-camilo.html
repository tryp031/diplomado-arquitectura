1. Alcance y requisitos

El proyecto es el Reto de Latencia Mínima: un sistema que recibe un estímulo y responde con la menor latencia posible. Se resuelve de dos maneras distintas, llamadas variantes, para poder compararlas:

  • TCP Python: cliente y servidor que se comunican por TCP, escritos en Python.
  • Memoria compartida C: cliente y servidor escritos en C que se comunican por memoria compartida, sin pasar por la red.

Una interfaz web enciende las variantes y permite probarlas desde el navegador. El proyecto tiene, entonces, tres piezas. Este manual cubre la instalación de las tres:

PiezaQué esQué necesita
Interfaz webEnciende los servidores y permite probarlos desde el navegadorPython 3.9 o superior
TCP PythonCliente y servidor TCP en PythonPython 3.9 o superior
Memoria compartida CCliente y servidor en C que se comunican por memoria compartidaCompilador de C, make y un sistema POSIX (macOS, Linux o WSL2)

No hay que instalar bibliotecas: sin pip install, sin npm, sin node_modules. Todo usa la biblioteca estándar de Python y de C. Para instalar Python, el compilador o WSL2 hace falta internet. Además, la interfaz web carga React y las tipografías desde un CDN (cdnjs.cloudflare.com y Google Fonts), así que necesita conexión a internet cada vez que se abre en el navegador; las variantes y el resto del sistema no la necesitan.

2. Elegir el camino

La interfaz y TCP Python corren en cualquier sistema. Memoria compartida C usa memoria compartida POSIX, que Windows nativo no ofrece, así que hay tres caminos:

CaminoQué correPara qué sirve
macOS o LinuxTodo: interfaz, TCP Python y Memoria compartida CTodo el sistema
Windows con WSL2Todo: interfaz, TCP Python y Memoria compartida CTodo el sistema, dentro de Windows
Windows nativoInterfaz y TCP PythonUsar la interfaz y TCP Python, sin Memoria compartida C

3. Instalación por plataforma

3.1 macOS

  1. Instalar las herramientas de línea de comandos, que traen el compilador y make: 
    xcode-select --install
  2. Comprobar Python: python3 --version debe mostrar 3.9 o superior. Si no, instalarlo desde https://www.python.org/downloads/.

3.2 Linux

En Debian o Ubuntu:

sudo apt update && sudo apt install -y build-essential make python3

En otras distribuciones se instalan los equivalentes: un compilador de C (gcc o clang), make y Python 3.9 o superior.

3.3 Windows nativo (interfaz y TCP Python)

  1. Instalar Python 3.9 o superior desde https://www.python.org/downloads/. Marcar la casilla «Add python.exe to PATH» durante la instalación.
  2. Copiar la carpeta del proyecto en el equipo (ZIP o clon del repositorio).

No se necesita nada más. Con este camino Memoria compartida C no está disponible. Para tenerla, seguir con 3.4.

3.4 Windows con WSL2 (sistema completo)

  1. Verificar que WSL está instalado. En PowerShell: 
    wsl -l -v
    Tiene que aparecer al menos una distribución (por ejemplo Ubuntu) con VERSION 2. Si no aparece ninguna, ejecutar wsl --install, reiniciar el equipo y volver a comprobar.
  2. Entrar a WSL y ubicarse en el proyecto. La unidad C: de Windows es /mnt/c dentro de WSL (D: es /mnt/d, y así con las demás). Si la ruta tiene espacios, va entre comillas: 
    wsl
cd "/mnt/c/ruta/al/proyecto/reto-latencia-group2"
  3. Instalar make y el compilador, si faltan. Se comprueba con make --version y cc --version; si alguno dice command not found: 
    sudo apt update && sudo apt install -y build-essential make
  4. Comprobar Python dentro de WSL: python3 --version. Ubuntu suele traerlo; si no, sudo apt install -y python3.

Desde aquí, todo el trabajo con el proyecto se hace dentro de WSL. El navegador sigue siendo el de Windows.

4. Arranque

SistemaComando
macOS, Linux o WSL2./iniciar.sh
Windows nativoDoble clic en iniciar.cmd, o desde PowerShell: .\iniciar.ps1

El arranque hace tres cosas, en este orden:

  1. Compila lo que la máquina pueda compilar en C y lo indica con una línea memoria-compartida-c ok en pantalla. Si no hay compilador, sigue sin ella.
  2. Levanta la interfaz web, que queda escuchando en http://127.0.0.1:8080.
  3. Abre el navegador en esa dirección. Si no se abre solo, abrirla a mano.

Para usar otro puerto: ./iniciar.sh 8081 o .\iniciar.ps1 8081.

Puede aparecer una línea control-dominio ok más. El arranque compila todo lo que tenga Makefile dentro de sistema/, y ahí también vive control-dominio: una herramienta aparte que mide cuánto cuesta clasificar un host, no una de las dos variantes que muestra la interfaz. Verla compilar es normal; no aparece como tarjeta en pantalla.

Windows: iniciar.cmd no arranca Memoria compartida C. En Windows nativo no hay compilador ni memoria compartida POSIX; el script continúa y deja funcionando la interfaz y TCP Python. Para Memoria compartida C hay que arrancar desde WSL2 con ./iniciar.sh. No ejecutar los dos a la vez: comparten el puerto 8080.

4.1 Puertos que usa el sistema

PuertoQuién lo usa
8080Interfaz web
9101Servidor de TCP Python
9103Identificador de Memoria compartida C. No abre un socket: el número solo da nombre a su región de memoria compartida

4.2 Encender las variantes y detener todo

Desde la interfaz, cada variante se enciende y se apaga con su propio botón Arrancar / Parar, o todas a la vez con Arrancar todas / Parar todas. Para detener el sistema completo, Ctrl+C en la terminal donde se ejecutó el arranque.

5. Verificar la instalación

5.1 Diagnóstico automático

Antes de arrancar, o cuando algo no funciona, el propio proyecto dice qué tiene la máquina y qué le falta, con el comando para conseguirlo:

SistemaComando
macOS, Linux o WSL2python3 doctor.py
Windowsdoctor.cmd (doble clic) o .\iniciar.ps1 -Doctor

El diagnóstico revisa la versión de Python, que los archivos del proyecto estén completos, que el puerto 8080 esté libre, si hay compilador y make, si hay WSL2 (en Windows) y qué variantes están disponibles en esa máquina. Termina con un veredicto y el comando de arranque que corresponde.

5.2 Lista de comprobación

#ComprobaciónResultado esperado
1doctor (5.1)Termina con «Todo listo» o, en Windows nativo, con «Podés arrancar el proyecto»
2Arranque (4)La terminal muestra la dirección http://127.0.0.1:8080 y el navegador abre la interfaz
3Durante el arranque, línea memoria-compartida-c ok (macOS, Linux, WSL2)Compiló. Si no aparece, ver 6
4En la interfaz, arrancar TCP PythonFigura como ACTIVO
5En la interfaz, arrancar Memoria compartida C (macOS, Linux, WSL2)Figura como ACTIVO
6En la interfaz, con una variante arrancada, enviar un estímulo con la IP 192.168.1.10Responde con un veredicto (esa IP no está en la tabla, así que devuelve DESCONOCIDO)

Con esto la instalación queda verificada. Para qué hace cada botón y qué significa cada número en pantalla, ver el manual de uso, sección 2.

6. Problemas frecuentes

SíntomaCausaQué hacer
Windows: «No encontre Python 3»Python no está instalado o no está en el PATHInstalarlo (3.3) marcando «Add python.exe to PATH» y volver a abrir la terminal
El puerto 8080 está ocupadoOtra aplicación, u otra copia del proyecto, lo usaArrancar en otro puerto: ./iniciar.sh 8081
Un mensaje dice que el puerto 9101 ya está ocupadoUn proceso ajeno a la interfaz lo tieneLa interfaz muestra el comando para ver quién lo usa y liberarlo
Windows: la interfaz abre pero Memoria compartida C no arrancaWindows nativo no tiene memoria compartida POSIX ni compiladorLa interfaz lo avisa al intentar arrancar Memoria compartida C, con el comando wsl --install. Usar WSL2 (3.4) y ./iniciar.sh
make: command not found o cc: command not foundFalta el compiladorInstalarlo según la plataforma (3.1, 3.2 o 3.4)
Memoria compartida C no aparece como compiladaError de compilaciónEjecutar make -C sistema/memoria-compartida-c y leer el error. El Makefile ya define lo que Linux necesita; una copia antigua del proyecto puede no tenerlo
Al volver a arrancar, el puerto 9101 aparece ocupado sin haber nada abiertoLa ventana de la interfaz se cerró de golpe y dejó el servidor de TCP Python en marchaVer quién lo tiene y cerrarlo: en Windows netstat -ano | findstr :9101 y taskkill /PID <número> /F; en macOS, Linux y WSL2 lsof -nP -iTCP:9101 -sTCP:LISTEN y kill <número>. Para evitarlo, cerrar con Ctrl+C
La interfaz no se muestra aunque el servidor esté en marchaLa página carga React desde un CDN y el equipo no tiene conexión a internetConectarse a internet y recargar. El servidor y las variantes funcionan sin conexión
Dentro de WSL, la ruta no existeLos espacios de la ruta rompen el comandoPoner la ruta entre comillas, con /mnt/c en lugar de C:\
El navegador abrió antes de que el servidor estuviera listoEl arranque abre la pestaña tras una espera cortaRecargar la página

Si nada de esto resuelve el problema, ejecutar el diagnóstico (5.1) y compartir su salida completa: dice el sistema, la versión de Python y qué falta.
